01 · Architecture and request flow · before / after

Before: a separate auth proxy guards the Service. After: the Gateway asks that same proxy, then EPP picks the Pod.

Before · NIMService as Run:ai exposes it today

Same blind Pod pick as LWS, plus one structural difference: the oauth2-proxy is its own Deployment in front of the NIM Service, not a sidecar in the Pod.

🆕 NEW rendered by the InferenceEndpoint controller today · 🔜 PLANNED proposed, not built · green request path · orange cold / fallback path · blue dotted internal · dashed grey = config / metrics
1. Client sends the request to the Run:ai URL; the Ingress / Route / HTTPRoute terminates TLS.
2. Ask: is the serving port protected?
   → yes: forward to the oauth2-proxy Service :80; the proxy validates and forwards to the NIM Service.  ✓ auth here
   → no:  forward to the NIM Service directly.
3. kube-proxy picks ANY frontend Pod at random.                          ⚠ no load awareness
4. NIM runtime (TRT-LLM / vLLM) generates; multi-node workers stay internal.
5. Response streams back the same way.                                   ✓

After · same workload, Gateway + EPP in front, existing auth proxy reused as an ext_authz check

Pod-direct routing skips the NIM Service, and with it the oauth2-proxy Deployment that stood in front of it. Proposed fix: the Gateway asks that same proxy "allowed?" (ext_authz on /oauth2/auth) before consulting EPP. The bytes never pass through the proxy; only the decision does.

🆕 NEW rendered by the InferenceEndpoint controller today · 🔜 PLANNED proposed, not built · green request path · orange cold / fallback path · blue dotted internal · dashed grey = config / metrics
1. Client sends the request to the hostname in routing.hostnames; the Gateway terminates TLS.
2. Protected only: Gateway calls the existing oauth2-proxy /oauth2/auth with the request headers → 200 or 401.  ⚠ 🔜 ext_authz policy must exist
3. Gateway asks EPP over gRPC: "which frontend?"
4. EPP scores the ready frontends (if NIM metrics are compatible) and returns Pod IP:HTTP port.  ✓
5. Gateway forwards straight to that Pod. Not the Service, not gRPC, not metrics port.
6. NIM runtime generates; workers stay internal.                                           ✓ identical to before
7. Response streams Pod → Gateway → client. EPP is not in the stream.                      ✓

Detailed sequence · one request on the new path

Same shape as LWS except step 2: the Gateway asks the existing oauth2-proxy Deployment for a decision, because the NIM Pod has no sidecar of its own.

🆕 NEW rendered by the InferenceEndpoint controller today · 🔜 PLANNED proposed, not built · green request path · orange cold / fallback path · blue dotted internal · dashed grey = config / metrics
0. EPP scrapes the NIM metricsPort on every ready frontend.
1. Client sends POST /v1/chat/completions to nim.example.com with a bearer token.
2. Protected: Gateway → ext_authz → existing oauth2-proxy /oauth2/auth → allow or 401.      ⚠ 🔜 policy must exist
3. Gateway asks EPP over ext_proc.
4. EPP drops unready frontends, scores them if NIM exposes compatible metrics, picks one.  ⚠ else weight 0 → round-robin
5. EPP answers with Pod IP and the HTTP target port.
6. Gateway forwards to that Pod. Not the Service, not the gRPC port, not the metrics port.  ✓
7. NIM runtime generates; multi-node workers stay internal.
8. Tokens stream back within the 300 s route budget.
9. Client receives 200 and the stream.                                                      ✓

🧠 LWS brings its own bouncer inside the Pod. NIM left the bouncer at the old door; the new door needs one too.

03 · Lifecycle flows

Operator and HPA keep capacity; the endpoint follows

HPA scales 1 → 3

1. HPA raises replicas on the operator-managed Deployment.
2. New frontends start; model/cache warm-up runs.         ⚠ ready probe may pass early
3. Pods ready → EPP sees them via the selector.            ✓ automatic
4. Metrics scraped → they start winning requests.

Operator upgrade / image change

1. Operator rolls the Deployment.
2. Old Pods unready → EPP stops picking them.              ✓
3. New Pods ready → added.                                 ✓
4. Ask: did the operator change Pod labels or ports?
   → yes: selector or port now wrong; pool silently empty. ✗ pin and test per operator version

Multi-node NIM

1. Operator creates leader (frontend) + worker Pods.
2. Selector must match frontends only.                     ⚠ verify labels
3. Workers never receive Gateway traffic.                  ✓
4. Autoscaling is excluded in multi-node; replicas fixed.

Replicas → 0 / all unready

1. Pool empty; EPP has no candidate.
2. Gateway returns 5xx.                                    ✗ no activation mechanism
3. Endpoint Ready stays True.                              ⚠ misleading
→ BackendsAvailable condition; document no scale-to-zero for NIM.
04 · Risks and what to change

Auth is the gate; everything else is verification

ConcernWhy it bites NIMWhat to change, whereSize
Auth not inheritedThe oauth2-proxy is its own Deployment in front of the NIM Service. The pool bypasses the Service, so a protected NIM becomes public on the new hostname.Reuse, do not duplicate: render a Gateway ext_authz policy (Envoy Gateway SecurityPolicy or equivalent) whose target is the existing oauth2-proxy Service /oauth2/auth. Controller: if authorizationType ≠ public and no such policy is bound, Ready=False, reason AuthPolicyMissing.M
Wrong portService port, HTTP target port, gRPC port and metrics port are four different numbers.Run:ai resolver: take the HTTP container port from the rendered NIMService; reject gRPC-only workloads for the first version.S
Label driftPod labels are set by the NIM operator and can change between operator versions.Resolve labels from the live NIMService status / Deployment selector, not from a constant. Pin supported operator versions in E2E.S
Scorer compatibilityqueue / KV / prefix scorers expect vLLM metric names. NIM on TRT-LLM exposes different metrics.Per-runtime validation table; weight 0 for unsupported scorers; document that NIM may fall back to plain load spreading.S
Readiness vs model healthModel download / cache warm-up can outlive the readiness probe.Prefer the operator's own readiness; add EPP filter for missing metrics.S
Replicas = 0No activator.BackendsAvailable condition.S
Route path / timeoutOnly /v1, 300 s.routing.pathPrefixes, routing.requestTimeout.S

Total to production: M for public NIM, L for protected NIM because of the new Gateway auth policy resource.
