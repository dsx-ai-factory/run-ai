## Existing controllers/hooks mapping
**How to read this?**

- The following table is a summary of all compute components (reconciler, controller, webhooks) related to restart, their responsabilities.
  
- Every column but the last one related to `DW` solution
  
- The last column `WorkloadRunner support (?)` is a high level summary of what needs to be done to support `WLR`
  

| # | Type | Component | Part of | What | Phases | CRDs | Responsibilities | Watches | WorkloadRunner support (?) |
|---|---|---|---|---|---|---|---|---|---|
| 1 | Mutating webhook (`/mutate-distributedworkload`) | DW workflow-id mutator | advice-restart-controller | Stamps `heimdall.nvidia.com/workflow-id` label on the DW so Heimdall monitors it | DW CREATE only | Mutates DW (label only) | Label value = CP workloadId or fresh UUID; skip if not PyTorchJob, opt-out annotation `run.ai/disable-ajr-integration`, idempotent if present | n/a | Add WLR support |
| 2 | ValidatingAdmissionPolicy (CEL, no pod) | `runai-heimdall-workflow-id-immutable` | go-operator operand (advice-restart-controller) | Denies removing/changing the workflow-id label once set | DW UPDATE | Validates DW | Heimdall must not lose track of a job mid-flight | n/a | Add WLR type support to operand |
| 3 | Reconciler | AdviceController | advice-restart-controller (standalone deployment) | Translates Heimdall `Advice` CRs into `RestartRequest` CRs + events | Advice created; RR phase transitions | Reads Advice, PyTorchJob (top-owner walk), DW (phase, affinity); creates RR; never writes Advice | State filter (only `ADVICE_STATE_RESTARTED`); dedup per advice; retry cap `maxRetriesPerAdvice`=3; lifetime cap `restartLimit`=3 succeeded RRs per workload; eligibility (skip Suspended/Suspending/Completed); builds node-exclusion overrides (hostname NotIn affinity); log vs action mode | `For(Advice)` + `Watches(RR)` mapped via `run.ai/advice-name` label, phase-transitions only | Add WLR handler: union exclusions with current `instructions.nodeConstraints`, emit one fixed-path patch; no Karta in advice controller |
| 4 | Validating webhook (`/validate-restartrequest`) | RR validator |  | Admits RR create/update | RR CREATE/UPDATE | Validates RR; reads DW (exists + generation) | GVK allowlist (DW only); workload-name label matches ref; generation match; override-path allowlist (`/spec/nodeAffinityRequired`, `/masterSpec/nodeAffinityRequired`); ONE active RR per workload; spec immutable after create | n/a | - Move to anyworkload |
| 5 | Reconciler | HandoffReconciler ("restart-handoff") | workload-controller | Owns RR lifecycle; hands the DW to the restart reconciler and takes it back | RR created; RR terminal; DW deleted | Mutates DW (label+managedBy), RR (finalizer, status.phase), ownerRef DW->RR | Finalizer `run.ai/restart-request-finalizer`; single atomic flip: label `run.ai/request-ref`=RR UID + `spec.managedBy=restart-controller`; rejects second concurrent RR (fails it); on terminal RR clears label+managedBy + emits RestartSucceeded/Failed; fails RR if workload gone | `For(RestartRequest)` + `Watches(DW, delete-only predicate)` | - Move to anyworkload |
| 6 | Validating webhook | DW managedBy validator | workload-controller | Freezes the restart protocol against external edits | DW UPDATE (mid-restart) | Validates DW | Enforces `managedBy` <-> `request-ref` label consistency + label immutability | n/a | - Move to anyworkload |
| 7 | Reconciler | WorkloadRestartReconciler ("restart-controller") | workload-controller | Executes the restart on the handed-off DW | Restart window (managedBy=restart-controller) | Reads RR (via request-ref UID lookup); mutates DW status+spec; DELETES PyTorchJob; writes RR status | Generation-delta fence (1=fresh, 2=already applied, else fail RR); DW `phase=Restarting`, `restartCount++` (idempotent); dry-run + persist spec overrides; delete framework object by `spec.jobType`; ack RR Succeeded when framework confirmed gone / Failed on 10m deletion timeout | `For(DW)` with `managedBy=restart-controller` + generation-changed predicates | - Move to anyworkload |
| 8 | Reconciler | DistributedWorkloadReconciler | workload-controller | Normal owner; recreates the framework object after handback - **this recreation IS the restart** | Post-handback (managedBy empty) | Reads DW; CREATES PyTorchJob | Refrains while handed off (predicate + in-loop guard); framework Get NotFound -> rebuild -> Create with the patched spec | `For(DW)` with `managedBy==""` predicate | replaced by Anyworkload-controller (dromos) |

## DW fields and gaps in WLR 

The table below maps fields from the `DW` manifest and how they map in `WLR`.

| DW field (YAML path) | DW context (who / how / when) | Verdict | Equivalent in WLR |
|---|---|---|---|
| `status.phase` = `Restarting` | • **Who**: WorkloadRestartReconciler (writer)<br>&nbsp;&nbsp;**How**: sets `phase=Restarting` together with `restartCount++`<br>&nbsp;&nbsp;**When**: during restart execution (generation delta 1 or 2)<br>• **Who**: cluster-sync (reader)<br>&nbsp;&nbsp;**How**: phase not in allow-set, degraded to `PHASE_UNKNOWN` in CP<br>&nbsp;&nbsp;**When**: every sync pass<br>• **Who**: advice controller (reader)<br>&nbsp;&nbsp;**How**: eligibility check on phase (skips Suspended/Suspending/Completed)<br>&nbsp;&nbsp;**When**: each Advice reconcile<br>• **Who**: workload-overseer / workload-exporter (readers)<br>&nbsp;&nbsp;**How**: finite-phase guard / phase metric label<br>&nbsp;&nbsp;**When**: their reconcile / scrape loops | **GAP** - probably not needed since no use | No `Restarting` in the WLR phase enum. Not meaningful use. Drop and fix E2E to use status for `RR` |
| `status.restartCount` | • **Who**: WorkloadRestartReconciler (writer)<br>&nbsp;&nbsp;**How**: increments alongside `phase=Restarting`<br>&nbsp;&nbsp;**When**: at restart start<br>• **Who**: DW status aggregator (preserver)<br>&nbsp;&nbsp;**How**: keeps the value across the child-absent window<br>&nbsp;&nbsp;**When**: every status recompute<br>• **Who**: e2e (only reader; never synced to CP)<br>&nbsp;&nbsp;**How**: asserts the counter value<br>&nbsp;&nbsp;**When**: after restart | **GAP** - probably not needed since no use | No such field in WLR. Drop since not used. Check impact in e2e. |
| `spec.managedBy` (ownership + gen-bump signal) | • **Who**: HandoffReconciler (writer)<br>&nbsp;&nbsp;**How**: sets `restart-controller` in one Update with the `request-ref` label; clears it on completion<br>&nbsp;&nbsp;**When**: handoff and handback<br>• **Who**: DistributedWorkloadReconciler (reader)<br>&nbsp;&nbsp;**How**: yields when non-empty (predicate + in-loop guard)<br>&nbsp;&nbsp;**When**: every DW event<br>• **Who**: WorkloadRestartReconciler (reader + self-healing clear)<br>&nbsp;&nbsp;**How**: claims via `managedByPredicate("restart-controller")`; clears it when the label/RR is missing<br>&nbsp;&nbsp;**When**: every DW event during the restart window<br>• **Who**: DW validating webhook (guard)<br>&nbsp;&nbsp;**How**: allows only `""`/`restart-controller` + label consistency<br>&nbsp;&nbsp;**When**: DW UPDATE admission | **GAP** - Add WLR CRD | Need this to keep track of ownership. Introduce as spec change to CRD due to generation bump, we want to keep this behavior. Add this in the same structure since it's a known concept in K8S workloads. |
| `labels["run.ai/request-ref"]` (RR lock) | • **Who**: HandoffReconciler (writer)<br>&nbsp;&nbsp;**How**: sets the RR UID atomically with `managedBy`; refuses if a different UID is already present (one active restart lock); deletes on completion<br>&nbsp;&nbsp;**When**: handoff and handback<br>• **Who**: WorkloadRestartReconciler (reader + self-healing clear)<br>&nbsp;&nbsp;**How**: resolves the RR from the UID; clears label + `managedBy` when the RR can't be resolved<br>&nbsp;&nbsp;**When**: each restart reconcile<br>• **Who**: DW validating webhook (guard)<br>&nbsp;&nbsp;**How**: enforces consistency with `managedBy`<br>&nbsp;&nbsp;**When**: DW UPDATE admission | PARTIAL | Generic label; nothing in dromos reads it, label to be added/removed. |
| `spec.jobType` (PyTorch filter + framework-CRD pick) | • **Who**: user/CP (writer)<br>&nbsp;&nbsp;**How**: part of the DW spec<br>&nbsp;&nbsp;**When**: DW creation<br>• **Who**: advice-restart DW mutating webhook (reader)<br>&nbsp;&nbsp;**How**: gates heimdall-label stamping on `JobType == "PyTorchJob"`<br>&nbsp;&nbsp;**When**: DW CREATE admission<br>• **Who**: restart executor (reader)<br>&nbsp;&nbsp;**How**: picks the framework CRD from `DistributedJobCRDsSupportedMap` to delete and poll<br>&nbsp;&nbsp;**When**: restart apply + finalize | 1:1 | Label `run.ai/workload-kind` is stamped on the WLR by the GVK LabelMutator at admission on Create+Update |
| `labels["heimdall.nvidia.com/workflow-id"]` (enrollment webhook) | • **Who**: advice-restart DW mutating webhook (writer)<br>&nbsp;&nbsp;**How**: stamps value = `workloadId` annotation, else fresh UUID<br>&nbsp;&nbsp;**When**: DW CREATE admission<br>• **Who**: Heimdall, external (reader)<br>&nbsp;&nbsp;**How**: monitors labeled jobs and posts Advice CRs<br>&nbsp;&nbsp;**When**: continuously<br>• **Who**: ValidatingAdmissionPolicy (guard)<br>&nbsp;&nbsp;**How**: CEL denies removing/changing the label<br>&nbsp;&nbsp;**When**: every DW UPDATE | PARTIAL | The injection point exists: the dromos WLR mutating webhook runs every `MutatorPlugin.WebhookMutate` on Create+Update, and being re-applied at admission it survives agent label wipes. |
| `annotations["workloadId"]` | • **Who**: CP (writer)<br>&nbsp;&nbsp;**How**: stamps the CP workload UUID<br>&nbsp;&nbsp;**When**: workload submission<br>• **Who**: advice controller (reader)<br>&nbsp;&nbsp;**How**: `GetRunaiWorkloadId(uid, annotations)` derives the `run.ai/workload-id` RR label<br>&nbsp;&nbsp;**When**: Advice processing (RR creation)<br>• **Who**: restart reconciler (reader)<br>&nbsp;&nbsp;**How**: same helper scopes its UID-indexed RR lookup<br>&nbsp;&nbsp;**When**: every restart reconcile<br>• **Who**: DW mutating webhook (reader)<br>&nbsp;&nbsp;**How**: uses it as the workflow-id value<br>&nbsp;&nbsp;**When**: DW CREATE admission | 1:1 | Already there: the agent stamps `workloadId` (CP workload UUID) on WLR metadata and inside the embedded child manifest on every sync `GetRunaiWorkloadId(uid, annotations)` works. |
| `annotations["run.ai/disable-ajr-integration"]` | • **Who**: user (writer, opt-out)<br>&nbsp;&nbsp;**How**: sets `"true"` on the DW<br>&nbsp;&nbsp;**When**: DW creation<br>• **Who**: advice-restart DW mutating webhook (reader)<br>&nbsp;&nbsp;**How**: skips stamping the workflow-id label, so Heimdall never monitors (no Advices, no auto-restarts)<br>&nbsp;&nbsp;**When**: DW CREATE admission only | 1:1 | Generic annotation, read the same way by an enrollment mutator. Caveat: it must arrive via the CP manifest to survive the agent's annotation-map replacement. |
| `metadata.generation` (G/G+1/G+2 delta state machine) | • **Who**: API server (writer)<br>&nbsp;&nbsp;**How**: bumps on every spec write (G+1 = handoff's `managedBy` write, G+2 = overrides patch)<br>&nbsp;&nbsp;**When**: each DW spec Update<br>• **Who**: advice controller (reader)<br>&nbsp;&nbsp;**How**: pins it into RR `spec.workloadRef.generation`<br>&nbsp;&nbsp;**When**: RR creation<br>• **Who**: RR validating webhook (guard)<br>&nbsp;&nbsp;**How**: rejects RRs whose pinned generation doesn't match the live DW<br>&nbsp;&nbsp;**When**: RR admission<br>• **Who**: WorkloadRestartReconciler (reader)<br>&nbsp;&nbsp;**How**: delta (DW.gen − RR.gen) drives the state machine: 1 = fresh handoff, 2 = overrides already applied, else Fail<br>&nbsp;&nbsp;**When**: every restart reconcile | PARTIAL | The field exists and bumps on any spec write |
| `spec.nodeAffinityRequired` (override patch path) | • **Who**: DW handler in advice controller (reader)<br>&nbsp;&nbsp;**How**: merges node exclusions (`kubernetes.io/hostname NotIn`) into the existing value, emits the RR JSON-patch at `/spec/nodeAffinityRequired`<br>&nbsp;&nbsp;**When**: Advice processing<br>• **Who**: restart executor (writer, via RR overrides)<br>&nbsp;&nbsp;**How**: dry-runs then persists the overrides patch (the G+2 bump)<br>&nbsp;&nbsp;**When**: restart apply<br>• **Who**: DW reconciler (consumer)<br>&nbsp;&nbsp;**How**: propagates the affinity into the recreated framework object<br>&nbsp;&nbsp;**When**: framework recreation after handback | PARTIAL | Exclusions go to `instructions.nodeConstraints` via a fixed-path RR patch; the NodeConstraints plugin merges them into pod affinity via Karta (mnnvl is production prior art for patch-through-Karta). |
| `masterSpec.nodeAffinityRequired` | • **Who**: same actors as `spec.nodeAffinityRequired`, for the master replica<br>&nbsp;&nbsp;**How**: read/merged only when `MasterSpec != nil`; patched at `/masterSpec/nodeAffinityRequired` (masterSpec is a top-level sibling of spec in the DW schema)<br>&nbsp;&nbsp;**When**: same points as the worker-side patch | 1:1 (subsumed) | The DW master/worker split is a schema artifact. In WLR + Karta, master and worker are per-instance keys in one call: `UpdateFragmentedPodSpec(map[instanceID]FragmentedPodSpec{"master": ..., "worker": ...})`. Strictly cleaner than the DW original. |
| `metadata.name` / `spec.name` child derivation (`GetChildName()`) | • **Who**: restart executor (reader)<br>&nbsp;&nbsp;**How**: `GetChildName()` + `spec.jobType` locate the framework object to delete, then poll until it is gone<br>&nbsp;&nbsp;**When**: restart apply and finalize (2s requeues, 10m deletion timeout) | PARTIAL | WLR has no `spec.name`; the child is whatever `spec.template.metadata.name` says. |
| `deletionTimestamp` / `ownerReferences` (top-owner walk) | • **Who**: advice controller (reader)<br>&nbsp;&nbsp;**How**: `findTopOwner` climbs the job's ownerRef chain to the DW<br>&nbsp;&nbsp;**When**: every Advice reconcile<br>• **Who**: HandoffReconciler (reader)<br>&nbsp;&nbsp;**How**: releases the RR finalizer only once the DW is gone/terminating<br>&nbsp;&nbsp;**When**: DW/RR deletion events<br>• **Who**: restart finalize (reader)<br>&nbsp;&nbsp;**How**: fails the RR when the framework's deletionTimestamp exceeds the timeout<br>&nbsp;&nbsp;**When**: finalize polling | PARTIAL | WLR is controller-owner of the child, so Pod → child → WLR is a standard ownerRef walk. Two catches: advice-restart-controller's RBAC cannot Get a WLR today (`runai-heimdall-workloads` ClusterRole lists pytorchjobs + DW only) |
| `metadata.uid` | • **Who**: advice controller (reader)<br>&nbsp;&nbsp;**How**: fallback to `GetRunaiWorkloadId` when the `workloadId` annotation is missing; feeds the `run.ai/workload-id` RR label<br>&nbsp;&nbsp;**When**: RR creation<br>• **Who**: restart reconciler (reader)<br>&nbsp;&nbsp;**How**: same fallback scopes the UID-indexed RR lookup<br>&nbsp;&nbsp;**When**: RR resolution during restart | 1:1 | Standard object metadata, identical; used as the workloadId fallback exactly as on DW. |
