⚠ Schema-version note. Left side is the runai Inference API DTO (what users submit). Right side is the target WorkloadRunner shape — instructions.networking.endpoints[] for Service + Ingress (post-PR #19525). The OAuth2-proxy sidecar for auth is composed at the CP composer level (Liran's design — in review): the sidecar is baked directly into the Knative Service template's pod spec (spec.template.spec.template.spec.containers[]), alongside the user container. The networking plugin has no InPod mode. Sidecar auth is a CP composer responsibility — not a runtime plugin. There is no instructions.initContainer.* field on WorkloadRunner. Today's shipped WLR schema is the v1 flat shape (services[], MaxItems: 1). Nothing migrates until PR #19525 + Liran's CP composer design land.

🔧 Where to implement. The CP-side composer lives in control-plane/workloads-and-policies/composer_v2/. Topic-specific composition: fields_composer_compute.go · fields_composer_security.go · fields_composer_storage.go · fields_composer_ports_urls.go. PodSpec / k8s-shape setters (env vars, scheduler name, DNS policy, host networking, auto-injected labels, …): setters_impl_k8s.go. Reference: PR #19903 (Ofer · merged) — sibling TW/IW/DW path; same patterns apply for InfW.
