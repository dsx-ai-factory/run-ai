# cluster-service — Build Context

**Type:** container
**Team:** Griffin Team
**Module:** `github.com/dsx-ai-factory/run-ai/control-plane/cluster-service`

## Make targets

Targets come from the service `Makefile` plus the shared includes
(`../../build/makefile/control-plane.mk`, `index.mk`, and the `golang.mk` /
`openapi.mk` / `versioning.mk` they pull in). The service overrides
`OPENAPI_GENERATOR_VERSION_SERVER` / `_CLIENT_GO` to `v7.12.0`, sets
`VERSIONED_CLIENT=true`, and runs Ginkgo with `GINKGO_PROCS=4` /
`GINKGO_COMPILERS=4`.

| Target | What it does |
|--------|-------------|
| `build` | `openapi-build` then `build-go` — bundle + generate OpenAPI, then compile the Go binary for amd64 + arm64 |
| `build-go` | `build-go-amd` + `build-go-arm` |
| `build-go-amd` | Compiles `cmd/main.go` for `GOOS=linux GOARCH=amd64` (FIPS `GOFIPS140=v1.0.0`) in the Go builder container → `bin/cluster-service-amd64` |
| `build-go-arm` | Same for `arm64` → `bin/cluster-service-arm64` |
| `test` | `test-ginkgo` — runs the Ginkgo unit/DB suites |
| `coverage` | Opens the HTML coverage report (`go tool cover -html`) |
| `lint` | `lint-go` — golangci-lint (shared config `../infra/lint/.golangci.yaml`) |
| `purify` | `purify-go` — `go fmt` + `go vet` + `go mod tidy` |
| `validate` | `openapi-validate` — validate the OpenAPI spec + generated-code up-to-date checks |
| `openapi-lint` | Lints the swagger bundle |
| `local-deploy` | `openapi-generate-code` + `build-go` + `docker-build-generic` + `docker-push-generic` (exports OS=linux ARCH=amd64) |
| `client-bump-version` / `client-bump-version-dev` | (from `pkg/client`) tag a prod / dev client release |

## Key build notes

- Generated code: OpenAPI server stubs (`internal/generated`) + versioned Go client (`pkg/client/generated`) are generated by openapi-generator `v7.12.0`, `VERSIONED_CLIENT=true`. `make build` runs `openapi-build` first; run OpenAPI generation before hand-building and never edit generated dirs.
- Runtime base image: final image is `FROM scratch`; a `registry.access.redhat.com/ubi9/ubi-minimal` stage supplies `/etc/passwd`, `/etc/group`, certs (`/etc/ssl`, `/etc/pki`) and a writable `/tmp`. Runs as user `65532:65532`. Bundles SQL migrations (`pkg/database/migrations/up|down`), the swagger bundle, and `NOTICE`.
- Build args: `TARGETARCH` (selects `bin/cluster-service-$TARGETARCH`).
- Build command (what local-dev.sh actually runs for this service): it is in `CP_GO_SERVICES`, so `build_go_service` runs, in two steps:
  1. Compile the amd64 binary in the builder container:
     `make build-go-amd OS=linux ARCH=amd64 DOCKERHUB_PROXY= GITHUB_TOKEN=`
     (`DOCKERHUB_PROXY=` pulls the Go builder image from Docker Hub; `GITHUB_TOKEN=` is emptied in the make call — the private-module token is applied elsewhere.)
  2. Build + load the image: `docker buildx build --platform linux/amd64 --provenance=false --load --build-arg TARGETARCH=amd64 -t runai-local/cluster-service:0.0.0 .`
     Image ref: `runai-local/cluster-service:0.0.0` (tag `0.0.0` — the CP chart appVersion; any other tag breaks the local deploy).
- Config: config-driven via registered structs in `pkg/config` (schema `cluster_service`); any config key is overridable by its uppercase env-var equivalent. Also registers the shared `dao-utils` database config and the authorization-client config. Do not hand-invent config keys — read `pkg/config/types.go`.
- Tests: Ginkgo suites; DB-backed suites (`pkg/test`, `pkg/database`) require a container runtime. No docker-compose integration-test target exists for this service.
