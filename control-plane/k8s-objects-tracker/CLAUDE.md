# k8s-objects-tracker — Build Context

**Type:** container
**Team:** Viper
**Module:** `github.com/run-ai/runai/control-plane/k8s-objects-tracker`

## Make targets

Targets come from the service `Makefile` plus the shared includes
(`../../build/makefile/control-plane.mk`, `index.mk`, and the `golang.mk` /
`openapi.mk` they pull in).

| Target | What it does |
|--------|-------------|
| `build` | `openapi-build` then `build-go` — builds the OpenAPI bundle + generated code, then compiles the Go binary for amd64 + arm64 |
| `build-go` | `build-go-amd` + `build-go-arm` — both arch binaries |
| `build-go-amd` | Compiles `cmd/main.go` for `GOOS=linux GOARCH=amd64` (FIPS `GOFIPS140=v1.0.0`) inside the Go builder container → `bin/k8s-objects-tracker-amd64` |
| `build-go-arm` | Same for `arm64` → `bin/k8s-objects-tracker-arm64` |
| `test` | `test-ginkgo` — Ginkgo/Gomega unit-test suites (DAO suites need Docker for PostgreSQL) |
| `coverage` | `test-go-acc` — coverage report (`GO_ACC_IGNORE=pkg/clients`) |
| `lint` | `lint-go` — golangci-lint in the builder container |
| `purify` | `purify-go` — `go fmt` + `go vet` + `go mod tidy` |
| `validate` | `openapi-validate` — validate the OpenAPI spec + generated code up-to-date |
| `openapi-lint` | Lint the swagger bundle |

## Key build notes

- Generated code: OpenAPI server stubs (`internal/generated`) are generated by openapi-generator `v7.12.0` (both `OPENAPI_GENERATOR_VERSION_SERVER` and `_CLIENT_GO` pinned in the Makefile). `make build` runs `openapi-build` first; never edit generated dirs.
- Runtime base image: final image is `FROM scratch`; a `registry.access.redhat.com/ubi9/ubi-minimal` stage supplies `/etc/passwd`, `/etc/group`, certs (`/etc/ssl`, `/etc/pki`) and a writable `/tmp`. Runs as user `65532:65532`. Bundles SQL migrations (`pkg/database/migrations/up|down`) and the swagger bundle (`swagger/_build`).
- Build args: `TARGETARCH` (selects `bin/k8s-objects-tracker-$TARGETARCH`).
- Build command (what local-dev.sh actually runs for this service): it is in `CP_GO_SERVICES`, so `build_go_service` runs, in two steps:
  1. Compile the amd64 binary in the builder container:
     `make build-go-amd OS=linux ARCH=amd64 DOCKERHUB_PROXY= GITHUB_TOKEN=`
     (`DOCKERHUB_PROXY=` pulls the Go builder image from Docker Hub; `GITHUB_TOKEN=` is emptied in the make call — the private-module token is applied elsewhere.)
  2. Build + load the image: `docker buildx build --platform linux/amd64 --provenance=false --load --build-arg TARGETARCH=amd64 -t runai-local/k8s-objects-tracker:0.0.0 .`
     Image ref: `runai-local/k8s-objects-tracker:0.0.0` (tag `0.0.0` — the CP chart appVersion; any other tag breaks the local deploy).
- No `pkg/client/` (no versioned Go client) and no `integration-tests/` directory; `pkg/clients/` holds outbound HTTP clients (authorization / clusters / org-unit), not a published client.
- Config: environment-variable driven with typed defaults; keys override via their uppercase env-var equivalents. PostgreSQL schema defaults to `k8s_objects_tracker`.
