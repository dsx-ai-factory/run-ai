Get a list of roles.

Retrieves a list of all available roles, including both NVIDIA Run:ai predefined roles and custom roles. Use this endpoint to review role configurations, permission sets and permissions.

Authorizations:
bearerAuth
query Parameters
limit
integer <int32> [ 1 .. 500 ]
Default: 50

The maximum number of entries to return.

offset
integer <int32>
Example: offset=100

The offset of the first item returned in the collection.

sortOrder
string
Default: "asc"
Enum: "asc" "desc"

Sort results in descending or ascending order.

sortBy
string (RolesSortFilterFields)
Enum: "name" "createdAt" "createdBy" "custom" "scopeType" "enabled"

Sort results by a parameter.

filterBy
Array of strings <= 10 items [^(name|createdAt|createdBy|custom|scopeType|e...]
Example: filterBy=name!=some-access-rule-name,createdAt>=2023-01-01T00:00:00Z

Filter results by a parameter. Use the format field-name operator value. Operators are == Equals, != Not equals, <= Less than or equal, >= Greater than or equal, =@ contains, !@ Does not contains, =^ Starts with and =$ Ends with. Dates are in ISO 8601 timestamp format and available for operators ==, !=, <= and >=.

search
string
Example: search=test project

Filter results by a free text search.

includeInternal
boolean
Default: false
Example: includeInternal=false

Migrate Access Rules From a Deprecated Role

Migrates access rules from a deprecated role to a non-deprecated role within the current tenant. For each access rule tied to the old (deprecated) role, a new rule is created under the new role (copying the subject, scope, and cluster) and then the old rule is deleted. If a matching new-role rule already exists for the same subject and scope, no new rule is created, but the old (deprecated-role) rule is still deleted and the pre-existing new rule is returned in the succeeded.preExisting bucket of the response. Each migration is performed in its own transaction - if either the create/lookup or the delete fails, the transaction is rolled back and the old access rule remains in place. Up to 100 access rules are migrated per call; callers should invoke repeatedly until all rules are migrated. The response lists the newly-created rules, the pre-existing rules that were reused, the IDs of old rules that were successfully deleted, and per-rule failures.

bearerAuth
