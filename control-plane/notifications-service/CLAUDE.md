# notifications-service — Build Context

**Type:** container (control-plane Go service)
**Team:** Phoenix (`artifact-metadata.json` → `jira.team_name`; Slack `@phoenix`)
**Module:** `github.com/dsx-ai-factory/run-ai/control-plane/notifications-service` (Go 1.26)

## What it is

Turns platform events into delivered notifications. Listeners (HTTP events API,
inbound SMTP, Kubernetes events, Prometheus alerts) → route/filter/enrich →
render per-channel templates → sinks (email/SMTP, Slack, Postgres history).
File-driven config (YAML) with `basic` and `advanced` providers; the
advanced provider serves an HTTP API to manage config at runtime.

## Key build notes

- **Control-plane Go service.** local-dev.sh (`CP_GO_SERVICES` → `build_go_service`) runs:
  ```bash
  make build-go-amd OS=linux ARCH=amd64 DOCKERHUB_PROXY= GITHUB_TOKEN=
  docker build --build-arg TARGETARCH=amd64 -t runai-local/notifications-service:0.0.0 .
  ```
- **Image tag: `0.0.0`** (CP tag, must match chart `appVersion`). Ref: `runai-local/notifications-service:0.0.0`.
- **Both arches:** amd64 (`build-go-amd`, reads `OS=`/`ARCH=`) and arm64 (`build-go-arm`, hardcodes `GOOS=linux GOARCH=arm64` — no `OS=`/`ARCH=`). Same tag; only `--build-arg TARGETARCH` differs. local-dev builds amd64 only.
- **Generated code (run before build if specs changed):** OpenAPI server stubs under `internal/*/openapi/generated` and Go clients under `pkg/client/generated/{notify,config_client,history}` — generated by `openapi-generator-cli` (server v7.12.0, chi router). The service's `make build` (`build_amd`/`build_arm`) runs the `generate-*` targets first; the shared `build-go-amd` that local-dev calls does NOT regenerate. Do not edit generated dirs by hand.
  - Specs: `internal/listen/http/openapi/notifications.yaml` (events), `internal/config/advanced/http_listener/openapi/listener_api.yaml` (config provider), `internal/history/openapi/endpoints_config.yaml` (history).
- **Base image:** Dockerfile multi-stage from `ubi9/ubi-minimal`. Two final targets: `integration` (ubi-minimal, for the test compose stack) and `prod` (`FROM scratch`, default deploy). Both non-root `USER 65532:65532`, `ENTRYPOINT ["./notifications-service"]`. Copies binary + `/swagger/` docs + `sinks_templates/`. Build arg `TARGETARCH`.
- **Artifact caching:** `artifact-metadata.json` sets `cache_artifacts: true`, `path_to_artifacts: bin/`.
- **Config:** env vars `CONF_PATH`, `ENV_CONFIG_PROVIDER` (`basic`/`advanced`), `ENCRYPT_DECRYPT_KEY`, `CONF_DB_HOST`; rest is a YAML config file (individual keys overridable by their uppercase env-var equivalents). Sample configs in `integration_tests/config/`.
- **Integration tests:** require Docker Compose (postgres + MailHog SMTP + slack stub). MailHog inbox at `http://localhost:8025/`.
