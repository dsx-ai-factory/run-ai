# gateway-hub — Build Context

**Type:** container
**Team:** Sphinx
**Module:** `github.com/dsx-ai-factory/run-ai/control-plane/gateway-hub`

gateway-hub is the Traefik forwardAuth sidecar for the control plane: three plain
Go HTTP handlers (`authentication-handler`, `extract-tenant-id`,
`workload-redirect-validation`) wired in `main.go`. There is **no `cmd/`
directory** — the module root is the build entry point (`BUILD_IN_PATH=.`).

## Make targets

Targets come from the service `Makefile` plus the shared includes
(`../../build/makefile/control-plane.mk`, `index.mk`, and the `golang.mk` /
`openapi.mk` they pull in). The service Makefile is thin: it sets
`SERVICE_NAME=gateway-hub`, `BUILD_IN_PATH=.`, `VERSIONED_CLIENT=true`, pins the
OpenAPI generator to `v7.12.0`, and stubs the JS/TS client-gen targets to no-ops
(gateway-hub has no frontend).

| Target | What it does |
|--------|-------------|
| `build` | `openapi-build` then `build-go` — builds the OpenAPI bundle + generated code, then compiles amd64 + arm64 binaries |
| `build-go` | `build-go-amd` + `build-go-arm` |
| `build-go-amd` | Compiles `.` for `GOOS=linux GOARCH=amd64` (FIPS `GOFIPS140=v1.0.0`) in the Go builder container → `bin/gateway-hub-amd64` |
| `build-go-arm` | Same for `arm64` → `bin/gateway-hub-arm64` |
| `test` | `test-go` — Go unit tests in the builder container (no integration suite) |
| `lint` | `lint-go` — golangci-lint in the builder container |
| `purify` | `purify-go` — `go fmt` + `go vet` + `go mod tidy` |
| `validate` | `openapi-validate` — verify the spec + generated code are up to date |
| `openapi-build` | Bundle the spec and regenerate server stubs + Go client |
| `openapi-lint` | Lint the built OpenAPI bundle |
| `docker-build-generic` / `docker-push-generic` | Build / push the container image (CI) |
| `client-bump-version` / `client-bump-version-dev` | Tag a new (or dev) `pkg/client` version |

## Key build notes

- Generated code: OpenAPI server stubs (`internal/generated`) + versioned Go client (`pkg/client/generated`) are generated by openapi-generator `v7.12.0` (`VERSIONED_CLIENT=true`). `make build` runs `openapi-build` first; never edit generated dirs.
- Runtime base image: final image is `FROM scratch`; a `registry.access.redhat.com/ubi9/ubi-minimal` stage supplies `/etc/passwd`, `/etc/group`, certs (`/etc/ssl`, `/etc/pki`), `nsswitch.conf`, and a writable `/tmp` (owned `65532:0`). Runs as user `65532:65532`, `EXPOSE 8181`.
- Build args: `TARGETARCH` (selects `bin/gateway-hub-$TARGETARCH`).
- Config model: file-driven. `pkg/config` registers a `Config` struct (keys `keycloak_url`, `management_realm`, `tenants_manager_url`, `cluster_service_url`) with defaults in code; the shared HTTP server config supplies `service_port` (default 8080, deployed as 8181). The config file is selected by `CONFIG_FILE_PATH`; any key is overridable by its uppercase env-var equivalent (`KEYCLOAK_URL`, `SERVICE_PORT`, …).
- Build command (what local-dev.sh actually runs for this service): it is in `CP_GO_SERVICES`, so `build_go_service` runs, in two steps:
  1. Compile the amd64 binary in the builder container:
     `make build-go-amd OS=linux ARCH=amd64 DOCKERHUB_PROXY= GITHUB_TOKEN=`
     (`DOCKERHUB_PROXY=` pulls the Go builder image from Docker Hub; `GITHUB_TOKEN=` is emptied in the make call — the private-module token is applied elsewhere.)
  2. Build + load the image: `docker buildx build --platform linux/amd64 --provenance=false --load --build-arg TARGETARCH=amd64 -t runai-local/gateway-hub:0.0.0 .`
     Image ref: `runai-local/gateway-hub:0.0.0` (tag `0.0.0` — the CP chart appVersion; any other tag breaks the local deploy).
- Tests: Go unit tests only (`net/http/httptest`); no docker-compose backing services.
