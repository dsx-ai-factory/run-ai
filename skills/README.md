# Run:ai Agent Skills

Agent Skills for the Run:ai platform — pre-built, evaluated workflows that teach an
AI agent (Claude Code, Codex, Cursor, …) how a Run:ai expert performs an operational
task on top of the Run:ai MCP tools. They follow the [agentskills.io](https://agentskills.io/specification)
spec and are intended for publication to **github.com/nvidia/skills** via the NVCARPS
pipeline once Run:ai is open-sourced.

## Layout
One directory per skill:

```text
skills/<skill-name>/
├── SKILL.md            # frontmatter (name + trigger-rich description) + workflow
├── references/         # deep-dive domain knowledge, loaded on demand
├── evals/
│   ├── evals.json      # trigger + output-quality test cases (agentskills schema)
│   ├── files/          # inputs staged into the eval sandbox (e.g. a mock MCP server)
│   ├── environment/    # Tier 3 container config (mcp_servers.toml, …)
│   └── README.md       # local evaluation results (mock and live runs)
├── BENCHMARK.md        # generated by NVSkills CI
├── skill-card.md       # generated by NVSkills CI
└── skill.oms.sig       # generated by NVSkills CI
```
`LICENSE` lives at the `skills/` root. A maintainer comments `/nvskills-ci` on a
pull request that changes a skill; NVSkills CI then pushes the three generated
files. Any later change to a skill's files breaks its signature until the next
`/nvskills-ci` run, so never edit the generated files by hand.

## Skills
- **runai-audit-assigned-quota** — audit GPU quota fairness (starved vs over-borrowing
  per node pool, cause = borrowing vs over-subscription, and the correct fix). Read-only.
- **runai-get-workload-health-summary** — summarize workload health at overview or
  single-workload drill-down depth, including failed-workload node correlation and
  diagnostic hand-off. Read-only.
- **runai-get-cluster-health-summary** — one-screen HEALTHY / DEGRADED / STUCK verdict
  per node pool with the dominant blocker: unhealthy nodes, GPUs lost, allocation and
  utilization, and a stuck scheduler vs a full pool. Read-only.
- **runai-get-utilization-overview** — which projects, departments, and node pools hold
  GPUs without using them: WELL_UTILIZED / UNDER_UTILIZED / IDLE from average and p95
  utilization, waste in idle GPUs and GPU-hours, and the idle workloads. Read-only.
